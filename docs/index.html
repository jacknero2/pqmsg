how it works

  1. On first login the client generates an ML-KEM-1024 + ML-DSA-87 keypair locally. The private half stays on your machine.
  2. Each message gets a random AES-256-GCM key, wrapped to every recipient device with ML-KEM and signed with ML-DSA.
  3. The server only ever stores and relays ciphertext — it can list conversations and see who is online, but not read anything.
  4. A background sync reconciles message order across devices (eventually consistent); delivered messages turn gold, undelivered stay red.
