Federated, post-quantum end-to-end encrypted messenger.
ML-KEM-1024 (FIPS 203) · ML-DSA-87 (FIPS 204) · AES-256-GCM

components

Two applications, distributed separately. The client is required to send or receive messages. The server is required to host an account; one installation serves any number of accounts and devices, and can optionally run the server directory (registry).

ClientGenerates and stores the device's private keys locally. Encrypts, decrypts, and displays messages.
ServerStores enrolled device public keys and encrypted message envelopes for its accounts, and relays ciphertext between clients. Never holds a private key.

architecture

Enrollment
On first login the client generates an ML-KEM-1024 keypair and an ML-DSA-87 keypair locally, then signs an attestation binding both public keys to the account and device name. The server verifies the attestation and publishes the public keys to its identity directory. Private keys are never transmitted.
Message encryption
Each message is encrypted under a random AES-256-GCM key. That key is wrapped separately for every recipient device via ML-KEM-1024 encapsulation, and the resulting envelope is signed with the sender device's ML-DSA-87 key. A server stores and relays the ciphertext; it cannot decrypt it.
Federation
Accounts are addressed as user@server. Each conversation has one deterministic home server — the lexicographically lowest participant server for direct messages, or a fixed assignment for groups — which stores and orders that conversation. Clients read and write to a conversation's home server independent of which server hosts their own account.
Directory (registry)
A server announces its address to a registry with a signed, self-authenticated request; the registry verifies the announcement against the server's public identity before listing it. Clients query a configured registry on startup to resolve usernames to servers without manual server selection.
Authentication
Login requires a password and a time-limited code sent to the account's registered email address. A trusted-device token can bypass the code on a given device for 30 days.
Consistency
Message order is authoritative on the home server. Clients reconcile their local view against that order on a fixed interval and mark delivery per recipient device.
